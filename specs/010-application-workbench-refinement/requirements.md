# Requirements

## 背景

`specs/009-v3-application-orchestration` 已经让 BLM 能表达应用服务接口、构件任务编排和参数变量映射。但当前应用工作台仍有四个明显问题：

1. 工作台中的“应用服务”实际是接口列表，缺少上层服务分组，接口数量变多后会散乱。
2. 接口请求/响应参数只能平铺，无法表达对象、数组和嵌套字段。
3. 应用编排区域缺少稳定的垂直滚动体验，步骤多时左侧拥挤。
4. 编排交互把步骤、参数和映射都堆在一列，不利于维护。

## 已确认判断

- 第一版“服务”只是接口聚合，不等同微服务、不等同领域服务、不绑定部署单元。
- 现有 `services[]` 继续兼容为“接口”集合，不做破坏性改名。
- 新增服务分组用于管理接口，接口通过弱引用归属到分组。
- 嵌套参数先作为设计结构和 UI 编辑能力，不引入 JSON Schema、OpenAPI 或复杂类型系统。

## 目标

- 应用工作台支持“服务 / 接口”两级管理。
- 接口参数支持嵌套编辑，Object/Array 类型可以维护子参数。
- 应用编排支持左侧步骤列表、右侧当前步骤详情和映射维护。
- 应用编排区域具有稳定垂直滚动，不因步骤和任务定义过多挤压页面。

## 追加问题：可用性打磨

用户在真实使用中发现当前工作台仍有不可用点：

1. 服务分组只能展示，不能可靠定义名称、修改名称、删除。
2. 服务分组不能展开/折叠，接口多时仍然拥挤。
3. 服务内接口不能在分组上下文中新建、修改、删除。
4. 接口不能重新设置所属服务分组。
5. 编排映射不应主要依赖手写字段，应以“下拉选择变量路径”为主。
6. 参数变量池需要能展开嵌套参数路径，至少覆盖 Object、Array/List、Map 这类结构的路径选择。

本轮优先修复“可用性断点”，不把编排升级为完整规则引擎。

## 不做

- 不把服务分组绑定到部署单元、Java 包、微服务或领域服务。
- 不引入 OpenAPI 完整导入导出。
- 不实现条件分支、循环、并行、补偿。
- 不实现变量路径自动校验或表达式语言。
- 不清理旧 `services[]` 字段名。

## 用户旅程

### Journey J010-01: 技术经理按服务分组管理接口

```gherkin
Scenario: 接口按服务分组展示
  Given 文档中存在服务分组“入库预约服务”
  And 接口“提交入库预约”归属该服务
  When 技术经理进入应用工作台
  Then 应先看到服务分组
  And 在服务分组下看到归属接口
```

### Journey J010-02: 技术经理维护嵌套接口参数

```gherkin
Scenario: 请求参数包含对象字段
  Given 接口“提交入库预约”正在编辑
  When 技术经理把请求参数“reservation”设为 Object
  And 添加子参数“warehouseUid”“items”
  Then 参数树应能显示父子层级
  And 文档中应保存到 `requestParams[].children`
```

### Journey J010-03: 技术经理维护编排步骤

```gherkin
Scenario: 右侧维护当前步骤映射
  Given 应用服务接口“提交入库预约”已有多个编排步骤
  When 技术经理选择步骤“保存入库预约”
  Then 右侧应展示该步骤的输入参数、输出参数、输入映射和输出绑定
  And 左侧只保留步骤列表和新增步骤入口
```

### Journey J010-04: 多步骤编排可滚动维护

```gherkin
Scenario: 步骤很多时应用编排仍可滚动
  Given 一个接口有多个编排步骤
  When 技术经理进入应用编排
  Then 步骤列表和右侧详情都应拥有独立垂直滚动能力
  And 页面不应因为任务定义下拉或映射行过多横向挤压
```

### Journey J010-05: 技术经理维护服务分组和组内接口

```gherkin
Scenario: 服务分组可以命名、折叠、删除，接口可以在组内维护
  Given 文档中存在服务分组“入库服务”和“出库服务”
  And “提交入库预约”接口属于“入库服务”
  When 技术经理修改“入库服务”的名称
  And 折叠再展开该服务
  And 在该服务下新建接口“查询预约”
  And 把“提交入库预约”重新归属到“出库服务”
  Then 页面应显示新的服务名称
  And 折叠时隐藏组内接口，展开时显示组内接口
  And 新接口应自动属于当前服务
  And 被重新归属的接口应移动到目标服务下
```

### Journey J010-06: 技术经理用下拉框选择编排变量

```gherkin
Scenario: 第三个任务的输入来源可以从前序任务变量中选择
  Given 一个接口有请求参数 reservation.warehouseUid
  And 编排已有三个任务：校验仓库、校验品种、保存预约
  And 前两个任务都有输入和输出参数
  When 技术经理选择第三个任务
  And 为第三个任务新增输入映射
  Then 来源下拉框应包含接口请求参数、前两个任务的输入变量、前两个任务的输出变量
  And 目标下拉框应包含第三个任务的输入参数
  And 变量路径应展开 Object、Array/List、Map 的子路径
```
