# 032 合并校验引导恢复 - 需求

## 需求梳理

本轮恢复旧版合并分析中的校验问题引导，属于旧版功能复刻，不改变合并算法和后端接口。

当前 Angular 合并弹窗会把 `validation_issues` 直接平铺展示，但用户无法判断这些问题是“等待冲突裁决后复检”还是“无冲突情况下仍存在内部模型异常”。旧版在这两个状态下给出不同说明。

## 用户旅程

```gherkin
Feature: 合并校验问题引导

Scenario: 有冲突时提示先处理冲突再复检
  Given 合并前检查返回冲突项和校验项
  When 用户查看合并分析结果
  Then 系统应展示“冲突处理后重新校验”的引导
  And 提醒用户先处理上方冲突项

Scenario: 无冲突但仍有校验项时提示内部异常
  Given 合并前检查没有冲突但返回校验项
  When 用户查看合并分析结果
  Then 系统应展示“模型内部引用异常”的引导
  And 提醒用户不要手动删除引用
```

## 边界

- 不实现校验项一键修复。
- 不改变“生成合并文档”的禁用规则。
- 不改变 `validation_issues` 数据结构。
