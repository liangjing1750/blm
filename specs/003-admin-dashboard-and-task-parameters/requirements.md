# 003 管理端仪表盘与任务参数定义

## 目标

本轮改动解决两个问题：

1. 管理端需要从“原始 JSON 查看器”升级为可排障的监控仪表盘，能清楚展示用户、连接、文档、日志以及它们之间的关系。
2. 任务定义需要补充输入参数、输出参数和任务地址，表达“任务如何被调用、需要什么、产出什么”，并且采用显式保存/取消，避免实时协作把半成品写入模型。

## 用户旅程

### 旅程 A：管理员排查协作与网络问题

- Given 管理端已经随主服务启动
- When 管理员打开 `http://host:8091`
- Then 页面应显示总体统计、活跃用户、连接明细、文档会话、最近日志
- And 页面应自动刷新，不需要手工反复刷新浏览器
- And 管理员可以下载诊断包

### 旅程 B：建模人员补充任务调用契约

- Given 建模人员正在编辑某个任务定义
- When 点击“查看/编辑参数”
- Then 弹窗展示任务地址、输入参数、输出参数
- When 在弹窗中新增、修改、删除参数并点击保存
- Then 参数一次性写入任务定义，并同步到引用了该任务定义的流程节点
- When 点击取消
- Then 不写入任何参数草稿

## 验收标准

- 管理端 `/api/status` 返回 `relationships.users`、`relationships.connections`、`relationships.documents`、`logSummary`。
- 管理端页面包含概览、用户、连接、文档、日志分区，并按固定间隔自动刷新。
- 任务定义存在 `address` 与 `parameters.inputs/outputs` 结构；老文档打开后自动补默认结构。
- 任务参数弹窗左右分栏展示入参和出参，支持新增、删除、编辑、保存、取消。
- 参数编辑过程中不调用 `markModified()`；只有保存时才触发修改。
- 静态语法检查和后端单元测试通过。
