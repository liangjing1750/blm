# 版本发布信息 20260513

## 发布范围

本版本围绕“流程原型/附件”能力、阶段视图预览一致性、附件保存性能和保存过程交互做了一轮集中优化。重点是让流程级附件真正归属到文档空间和流程目录下，降低大文件对文档保存的影响，并让保存期间的系统状态更清楚、更可控。

## 主要更新

### 1. 阶段视图预览一致性优化

- 优化阶段视图预览渲染，使预览效果与建模时保持一致。
- 调整预览导出链路，避免阶段视图和建模视图出现表达差异。

### 2. 流程原型/附件能力

- 将原“流程原型”扩展为“流程原型/附件”，支持上传 HTML、图片、PDF、Office 文档、Markdown、文本、CSV、JSON 等常见文件。
- 附件归属范围调整为文档空间下的流程附件，目录结构按文档和流程组织，便于导出后按流程名称查找。
- 附件索引与文档元数据分离，附件版本独立维护。
- 对可预览文件提供打开预览能力，对不可预览文档提供下载能力。
- 上传时增加文件类型边界，阻止可执行文件、脚本和压缩包等高风险类型。
- 删除附件增加确认，降低误删风险。

### 3. 附件存储和保存性能优化

- 新增附件上传接口，上传阶段先把二进制内容暂存到工作区临时上传目录。
- 保存文档时不再把大附件内容塞进 JSON 文档体，降低大文件附件对保存速度的影响。
- 文档保存改为优先写入元数据和附件索引，已有二进制附件不再重复读写。
- 历史版本快照只记录文档元数据和附件索引，不复制大附件实体，避免历史目录膨胀。
- 临时文件、上传暂存文件和回收站文件分别归入独立目录，减少工作区根目录混乱。

### 4. 保存过程交互优化

- 保存进度拆分为“准备保存、发送保存请求、等待服务器保存、保存完成”几个阶段。
- 修正原来进度条到 100% 后仍等待的问题：现在请求发送完成后会显示“数据已发送，正在等待服务器保存”，后端真正响应后才显示保存完成。
- 保存期间显示居中的全屏遮罩、转圈和进度条。
- 保存期间禁用保存、复制、导出等操作，并拦截键盘快捷操作，避免重复点击或并发保存。
- 保存成功后清理“附件已上传，保存后生效”的提示状态。

### 5. 后端稳健性修复

- 修复保存时历史快照复制附件目录可能导致卡住或抛错的问题。
- 保存流程增加互斥保护，避免并发请求同时写入同一文档造成状态不一致。
- 附件下载接口支持按文档、附件和版本定位文件。

### 6. 流程图视图增强

- 新增流程泳道图渲染，支持按角色拆分泳道，并与摘要图共用同一套流程结构模型。
- 流程结构统一为“节点、分支、连线”，线性图更名为“摘要图”，用于快速阅读主路径和分支概况。
- 优化摘要图和泳道图的连线、回退、自环、多行路径和多角色节点展示。
- 预览页同步流程图渲染能力，保证建模视图和预览视图表达一致。

### 7. 合并与 ID 机制优化

- 增加流程、流程节点、分支、连线、实体等业务 ID 的显式编辑入口，便于合并前人工消歧。
- 新文档和新增元素的默认 ID 生成改为更稳定的前缀加短标识策略，降低跨文档合并时的默认递增 ID 冲突。
- 合并校验增加重复业务 ID 检查，并将流程图模型中的分支和连线纳入合并范围。
- 保留隐藏 uid 作为非业务身份标识，业务 id 作为用户可读、可改的业务主键。

### 8. 并行编辑防覆盖

- 保存时新增文档 revision 乐观锁校验，前端保存会携带打开文档时的基线版本。
- 后端继续保留写锁，保证同一时刻只有一个写入动作落盘。
- 当保存版本落后于工作区最新版本时，自动使用现有三方合并能力进行 rebase。
- 非重叠修改会自动合并后保存；同一字段双改等冲突场景会阻止覆盖并返回冲突提示。

### 9. 产品版本标识

- 左上角 BLM 标识下方新增产品版本号，当前显示为 v1.0。

## 注意事项

- 本版本不兼容旧的原型文件存储假设；当前项目尚无原型旧数据，因此不做旧数据迁移。
- 附件版本与文档版本独立，文档历史版本记录附件引用和索引信息，不复制完整附件二进制。
- 大文件上传后，保存阶段应主要处理元数据和索引；如果仍感觉保存慢，建议继续结合后端耗时日志定位具体慢点。
