# 构件工作台三级 Tab 拆分设计

## 背景

当前构件工作台里的“组件构件”三级 tab 同时承载业务组件、业务构件、实体、任务等信息，内容密度过高，不利于查看和定位。用户希望保持工作台主体不变，只把该三级 tab 拆细，让“看组件”和“看构件详情”分开。

## 目标

构件工作台三级 tab 从 3 个调整为 4 个：

1. 业务组件
2. 业务构件
3. 实体定义
4. 应用服务

其中“业务组件”和“业务构件”替代原来的“组件构件”。

## 业务组件视图

业务组件视图是总览页，只回答两个问题：

- 当前有哪些业务组件。
- 每个业务组件下有哪些业务构件。

页面以组件卡片为主体。每个组件卡片显示组件名称、说明、构件数量和构件列表。构件列表里的构件项可以点击，点击后进入“业务构件”视图，并把该构件设为当前构件。

该视图不展开实体、任务、服务/API 等明细，避免重新变成高密度混合页。

## 业务构件视图

业务构件视图是构件详情页，默认逻辑为：

- 从业务组件视图点击某个构件进入时，显示该构件。
- 直接打开业务构件 tab 且没有当前构件时，显示第一个构件。

页面顶部提供：

- 返回组件视图按钮。
- 当前构件选择器。
- 构件基础信息。

主体只展示两类内容：

- 关联实体。
- 关联任务。

暂不展示服务/API，避免首屏再次拥挤。

## 状态流转

复用现有业务组件、业务构件、实体、任务定义数据。新增或复用一个 UI 状态保存当前构件，例如 `selectedConstructId`。

从业务组件点击构件时：

1. 设置当前构件。
2. 切换三级 tab 到业务构件。
3. 业务构件视图展示该构件关联实体和任务。

从业务构件点击返回时：

1. 切换三级 tab 到业务组件。
2. 保留当前构件状态，便于后续高亮或继续定位。

## 测试要求

需要补充组件工作台测试：

- 三级 tab 出现“业务组件”和“业务构件”，不再显示原来的“组件构件”。
- 业务组件视图只渲染组件卡片和构件列表。
- 点击构件后切到业务构件视图，并显示该构件的实体和任务。
- 直接打开业务构件视图时，没有当前构件则回落到第一个构件。
- 从业务构件返回业务组件视图后，当前构件状态保留。

## 非目标

本次不重做实体定义、应用服务、任务定义编辑器。
本次不引入新的业务数据结构。
本次不把服务/API 放进业务构件首屏。
