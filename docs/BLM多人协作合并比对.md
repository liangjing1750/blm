# BLM 多人协作合并比对

## 协作保存流程

```
用户 Ctrl+S → 冻结当前文档 → HTTP 发送 { baseSeq, document } → 服务端
服务端：
  1. submit-record 先落盘（100% 不丢失）
  2. baseSeq 匹配 → 快速路径（hash 相同跳过合并）
  3. baseSeq 不匹配 → 3-way 合并（base vs user vs server）
  4. 有冲突 → 不自动合并，返回冲突列表给用户决策
  5. 无冲突 → 自动合并，seq+1，保存历史快照
```

## 3-way 合并规则

合并引擎逐字段比较三个版本：

| 场景 | base | user（你的）| server（他人）| 结果 |
|------|------|------------|--------------|------|
| 仅你改了 | "A" | "B" | "A" | 用你的 "B" |
| 仅他人改了 | "A" | "A" | "B" | 用他人的 "B" |
| 都改了同一字段 | "A" | "B" | "C" | **冲突弹窗，你决定** |
| 都没改 | "A" | "A" | "A" | 不变 |

**关键保证**：非冲突字段永远不会丢失。你改了角色名、别人改了流程名 → 两个修改都保留。

## 冲突处理

```
检测到冲突 → 弹窗展示冲突字段
  ├── "保留我的版本" → 恢复冻结文档，标记待同步，下次 Ctrl+S 重新合并
  └── "使用服务端版本" → 接受服务端合并结果
```

两者都会保留 submit 原文，可随时从"历史记录 → 本地提交记录"找回。

## 旧 baseSeq 提交

如果你的本地版本基于很旧的 seq（如 seq=30，目前服务端是 seq=50）：

1. 内存查找 snapshot[30] → 命中则精确 3-way
2. 磁盘查找 history 中 seq=30 的快照 → 命中则精确 3-way
3. 都不命中 → 2-way combine 降级（默认保留服务端值）

**建议**：频繁 Ctrl+S 保持本地 seq 接近服务端，减少冲突概率。

## 比对功能

工具栏"比对"支持跨来源对比：
- 工作区文档（当前版本）
- 远端历史记录（历史快照）
- 本地提交记录（submit 草稿）

版本下拉框用分组（`<optgroup>`）展示，一次选择即可开始比对。

## 历史记录

工具栏"历史记录"提供双 tab：
- **远端历史记录**：每次保存的协作快照，含作者 + 版本号 + 变更摘要
- **本地提交记录**：每次 Ctrl+S 的原文，含用户 + 版本链，支持恢复

每个条目都有"打开"（只读预览）和"恢复"按钮。
